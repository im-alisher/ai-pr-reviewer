# AI Pull Request Reviewer

AI-powered, **read-only** review reports for public GitHub pull requests.

Paste a public PR URL, get an executive summary, potential bugs, security
findings, refactoring suggestions, complexity notes, and a risk score. Patch
suggestions (unified diffs) are generated only after an explicit **Generate
Patch** action, shown as copyable text — never applied, committed, or pushed.

## Features

- **PR analysis** — fetches metadata, changed files, diffs, and commit
  messages from the public GitHub REST API (no OAuth in V1).
- **AI review report**
  - Executive summary
  - Potential bugs
  - Security findings
  - Refactoring suggestions
  - Complexity notes
  - Risk score (0–100) with level, rationale, and factors
- **Suggested patches** (explicit opt-in only)
  - Unified diff viewer with syntax-aware line coloring
  - Copy single file, single suggestion, or all patches
  - Download `.diff` exports
  - Validated (hunk headers, safe repository-relative paths, conflict-marker
    detection) before display
- **Provider abstraction** — default provider is Groq; additional AI providers
  are pluggable through a registry.
- **UI** — responsive, dark mode support, loading and error states,
  shadcn/ui-style components on Tailwind CSS.

## Safety guarantees

- The AI **never modifies code** automatically.
- Fix/patch generation runs **only** after the user clicks **Generate Patch**.
- Patches are **suggestions only**: displayed, copyable, downloadable —
  never applied to any repository.
- No GitHub branches, commits, or PRs are ever created.
- Only the public GitHub REST API is used; no OAuth tokens in V1.
- The API validates PR URLs strictly (owner/repo/number) and only ever
  calls `api.github.com`.

## Repository structure

```
apps/
  web/                     React + Vite frontend
  api/                     NestJS API (analyze + patch endpoints)
packages/
  shared/                  Shared review models, URL parsing, risk utils
  github-client/           Public GitHub REST client (PR context fetch)
  ai-review-engine/        Provider abstraction, prompts, report parser
  patch-generator/         Unified diff validation + patch suggestions
tests/                     Vitest suites (unit + service level)
```

### Data flow

```
web (PR URL)
  └─> api POST /api/review/analyze
        ├─> github-client: metadata + files + commits + diffs
        └─> ai-review-engine: provider (Groq) → normalized ReviewReport
  └─> web renders report
user clicks "Generate Patch"  ← explicit approval boundary
  └─> api POST /api/review/patch
        ├─> github-client: fresh PR context
        └─> patch-generator: provider → validated unified diff suggestions
  └─> web renders diff viewer → copy / download (nothing is applied)
```

## Getting started

### Prerequisites

- Node.js >= 20
- npm >= 10

### Install

```bash
npm install
```

### Environment variables

No `.env` files are generated by this project. Set variables in your own
shell (or secret manager) when running the API:

| Variable        | Required | Default                     | Description                                              |
| --------------- | -------- | --------------------------- | -------------------------------------------------------- |
| `GROQ_API_KEY`  | Yes      | —                           | Groq API key used by the default AI provider.            |
| `GROQ_MODEL`    | No       | `openai/gpt-oss-120b`       | Groq model id used for reviews and patch generation.     |
| `AI_PROVIDER`   | No       | `groq`                      | Provider name to resolve from the registry.              |
| `GITHUB_TOKEN`  | No       | —                           | Optional GitHub token for higher API rate limits (public API only). |
| `PORT`          | No       | `3001`                      | API listen port.                                         |
| `CORS_ORIGIN`   | No       | (reflect request origin)    | Comma-separated allowed CORS origins.                    |

Without `GROQ_API_KEY`, the API boots normally and analysis requests fail
with a clear `ai_missing_api_key` error.

### Development

Runs API (port 3001) and web dev server (port 5173, `/api` proxied) together:

```bash
npm run dev
```

Open http://localhost:5173, paste a public PR URL such as
`https://github.com/owner/repo/pull/123`, and click **Analyze PR**.

### Production build

```bash
npm run build     # builds all packages, API, and web app
npm run lint      # ESLint across the monorepo
npm test          # Vitest suites
```

Start the API: `npm run start -w @ai-pr-reviewer/api`.

## API

| Method | Endpoint               | Body                                        | Response                     |
| ------ | ---------------------- | ------------------------------------------- | ---------------------------- |
| GET    | `/api/health`          | —                                           | Service health               |
| POST   | `/api/review/analyze`  | `{ "prUrl": "https://github.com/o/r/pull/1" }` | PR data + `ReviewReport`  |
| POST   | `/api/review/patch`    | `{ "prUrl": "...", "report": ReviewReport, "findingIds": ["optional"] }` | `PatchResult` (suggested unified diffs) |

Errors use a consistent shape:

```json
{ "statusCode": 503, "code": "ai_missing_api_key", "message": "..." }
```

Common codes: `invalid_pr_url`, `pull_request_not_found`,
`github_rate_limited`, `github_error`, `ai_missing_api_key`,
`ai_provider_error`, `ai_invalid_response`, `patch_generation_failed`.

## Testing

```bash
npm test
```

Suites cover shared URL/risk utilities, GitHub client mapping and error
handling, AI report parsing/normalization, unified diff validation, patch
payload parsing, patch export helpers, and the review service workflow
(injected GitHub client + mock AI provider — no network or API keys needed).

## Roadmap (not implemented in V1)

The following are intentionally **out of scope** for V1 and must not be
assumed to exist:

- **GitHub OAuth** — V1 uses only the public REST API without authentication.
- **Branch creation** — no branches are ever created.
- **Automatic PR creation** — no commits or pull requests are ever opened.
- **Multi-model support** — the provider abstraction and registry exist;
  additional first-class providers (OpenAI, Anthropic, local models) are
  planned but only Groq ships in V1.
